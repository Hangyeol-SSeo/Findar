# 작성
문항의 모든 요구에 답하면서 구상의 흐름을 자연스럽게 구현하세요. 구상은 방향이며 사실 자료가 아닙니다.
선정한 경험의 판단·행동·변화를 보여주세요. researchMode가 direct이면 회사 사실이 선택 이유나 기여 방향의 논거로 기능하도록 연결하세요. 조사 보고서를 요약하거나 회사 칭찬을 나열하지 마세요.
본문에 사용한 회사 사실과 개인 경험은 evidence에 원문 인용을 남기세요. perspective이면 회사 사실을 본문에 넣지 않아도 됩니다.
모든 서술 문장은 존댓말로 작성하세요. 명언형 도입, 추상적인 교훈, 매 문단의 억지 직무 연결을 피하세요. 문항이 요구하는 필수 근거가 없으면 needs_info로 반환하세요.

문항 요구별로 작성하세요. 견해형은 명확한 주장, 인과·작동 원리, 반론·한계를 연결하고 경험을 억지로 넣지 마세요. 자유형은 지원 직무에 맞는 하나의 메시지 아래 필요한 내용만 고르세요. 혼합형은 요구한 모든 부분에 답하세요.
사실 주장과 논리적 해석을 구분하세요. 개인 경험·동기·회사 사실·산업의 구체적 사례나 최신 현황은 자료로 뒷받침해야 합니다. 자료가 없는 최신 사실을 발명하지 마세요. 꼭 필요한 사실이 없다면 구체적인 보완 질문을 남기세요.
personalEvidence=optional인 순수 논증은 evidence=[]가 가능하지만 검증되지 않은 사실·수치를 포함해서는 안 됩니다. 제안한 관점은 과거부터 가진 신념이나 경험처럼 서술하지 말고 reviewNotes에 사용자의 관점 확인 사항을 남기세요.

견해형이라도 일반론이라는 이유로 사실 검증을 생략하지 마세요. “독점한다”, “기관 수준의 정보에 접근한다”, “기존 체계보다 빠르다”, “규제 공백에서 이루어진다”처럼 비교·현황·법규·효과를 단정하는 문장은 자료 근거가 필요합니다. 근거가 없으면 삭제하거나, 전제와 성립 조건을 명시한 가설·조건부 분석으로 바꾸세요. 단순히 문장 끝에 “생각합니다”를 붙여 사실 주장을 숨기지 마세요.
자료가 부족한 경우에도 논증 가능한 범위를 먼저 찾으세요. 견해는 본인이 제안하는 판단 기준, 조건에 따른 영향, 선택과 상충관계로 구체화할 수 있습니다. 공고는 직무 방향의 근거이며 산업 사실의 출처가 아닙니다. 회사 자료의 짧은 문장을 업계 전체 사실의 근거로 확대하지 마세요.
answer에는 실제 문단 줄바꿈을 넣으세요. JSON 문자열의 줄바꿈 이스케이프를 이중으로 쓰지 마세요. reviewNotes에 글자 수를 추정해 쓰지 마세요. 글자 수는 앱이 계산합니다.
