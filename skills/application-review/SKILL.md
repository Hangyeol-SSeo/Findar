# 편집
구상과 초안을 원자료에 대조하세요. 하위 질문·시간 범위가 빠졌는지, 회사명만 바꿔도 성립하는 지원동기인지, 회사 설명과 개인 경험이 따로 노는지 확인하세요.
회사 사실은 출처와 연결되고 해석은 사실처럼 단정하지 않아야 합니다. researchMode가 direct이면 선정한 회사 근거가 실제 논거로 사용되고 evidence에 포함되어야 합니다. 연결이 부자연스러우면 문장을 다시 설계하세요.
다른 문항과 같은 경험·메시지를 반복하는지, 첫 문장부터 반말이 있는지, 교훈형 도입이나 부풀린 수치가 있는지 검토하고 바로잡으세요.
본문에 새 사실을 추가하려면 반드시 원자료를 확인하세요. 글자 수를 맞추려고 문장을 중간에서 자르지 마세요. 사용자가 확인할 사항을 reviewNotes에 존댓말로 남기세요.

선택한 지원 직무의 업무·요구사항과 일치하는지, 다른 모집 직무의 요건을 섞었는지 확인하세요. 문항 충족, 주장과 근거의 연결, 구체성, 사실성, 범용적인 문구 남용을 각각 검토하고 부족한 부분을 다시 작성하세요.
견해형의 주장과 해석에 원문 인용을 강제하지 마세요. 대신 인과의 비약·근거 없는 일반화·반론 누락을 검토하세요. 구체적 산업 사실이나 최신 현황은 반드시 자료에서 확인하세요. 경험이 불필요한 문항을 경험 부족으로 중단하지 마세요.

견해형이라도 일반론이라는 이유로 사실 검증을 생략하지 마세요. “독점한다”, “기관 수준의 정보에 접근한다”, “기존 체계보다 빠르다”, “규제 공백에서 이루어진다”처럼 비교·현황·법규·효과를 단정하는 문장은 자료 근거가 필요합니다. 근거가 없으면 삭제하거나, 전제와 성립 조건을 명시한 가설·조건부 분석으로 바꾸세요. 단순히 문장 끝에 “생각합니다”를 붙여 사실 주장을 숨기지 마세요.
자료가 부족한 경우에도 논증 가능한 범위를 먼저 찾으세요. 견해는 본인이 제안하는 판단 기준, 조건에 따른 영향, 선택과 상충관계로 구체화할 수 있습니다. 공고는 직무 방향의 근거이며 산업 사실의 출처가 아닙니다. 회사 자료의 짧은 문장을 업계 전체 사실의 근거로 확대하지 마세요.
answer에는 실제 문단 줄바꿈을 넣으세요. JSON 문자열의 줄바꿈 이스케이프를 이중으로 쓰지 마세요. reviewNotes에 글자 수를 추정해 쓰지 마세요. 글자 수는 앱이 계산합니다.
