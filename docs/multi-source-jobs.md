# 금투협 게시판 밖의 증권업계 공고 수집 설계

상태: 1~3단계 구현(2026-10-29, 커밋 d10d1ad). 2026-10-28 작성, 2026-10-29 채널 전수 확인(2절 D) 반영. 구현하면서 바뀐 점은 10절.

## 0. 방향

- 목표는 다른 사이트의 공고를 전부 긁어 오는 것이 **아니다**. 증권업계 분류(금융투자업자, 유관기관·인프라, 인접 산업) 안에 있으면서 **금투협 채용 게시판에 공고를 올리지 않는 회사**의 공고만 따로 가져온다.
- 그래서 수집 단위는 출처 사이트가 아니라 **회사 목록(watchlist)**이다. 회사마다 "공고를 어디서 가져오는지"를 정해 두고, 회사가 쓰는 채용 시스템 종류(ATS 계열)별로 어댑터를 하나씩 만든다.
- 2026-10-19 초안의 "잡알리오 + 사람인 전체 수집"은 이 방향에 맞춰 축소한다(7절).

## 1. 조사 결과: 누가 금투협 게시판에 올리는가

자료: 금투협 회원사 명부(kofia.or.kr 회원사현황, 2026-10-27 수집, 595곳)와 Findar DB의 금투협 공고(2026-05-08 ~ 10-27, 2,485건, 347개사).
회사명은 `(구.…)`·`(주)`·공백을 지우고 영문 약어를 한글 발음으로 바꾼 뒤 맞췄다.

| 업권 | 회원 수 | 반년 동안 게시한 회사 | 공고 수 |
|---|---:|---:|---:|
| 정회원·증권 | 60 | 42 | 917 |
| 정회원·자산운용 | 333 | 213 | 1,230 |
| 정회원·선물 | 3 | 2 | 6 |
| 정회원·신탁 | 14 | 7 | 22 |
| 준회원·투자자문/일임 | 110 | 22 | 47 |
| 준회원·은행 | 27 | 9 | 70 |
| 준회원·보험 | 8 | 2 | 22 |
| 준회원·증권금융 | 1 | 1 | 1 |
| 준회원·기타(외국환중개·온라인소액투자중개·조합·체신관서) | 11 | 0 | 0 |
| 특별회원(사무관리·평가·신용평가·기타) | 28 | 18 | 58 |

정리하면:

- **국내 증권사 42곳은 전부 금투협에 무언가를 올린다.** 증권 정회원 중 0건인 18곳은 모두 외국계(서울지점·현지법인)다. 하지만 "올리는 회사"라고 다 올리는 것은 아니다. **경력·수시 채용은 오고, 신입 공채와 채용연계형 인턴은 자주 빠진다**(2절 D). 그래서 회사 단위 "게시 여부"가 아니라 채용 종류 단위로 봐야 한다.
- 자산운용은 120곳이 0건, 91곳이 1~2건이다. 대부분은 채용 자체가 드문 소형사다. 0건 중 눈에 띄는 곳은 외국계 운용사(피델리티, 슈로더, 얼라이언스번스틴, 누버거버먼, 브룩필드, 라살, 맥쿼리자산운용)와 타이거대체투자운용, 브이아이피자산운용, 삼성헤지·삼성SRA, 한국성장금융투자운용이다.
- 비회원이 올린 공고는 사실상 없다. 비회원으로 잡힌 30곳은 대부분 회사명이 바뀌었거나 표기가 다른 경우다(교보악사→교보자산운용, KIS자산평가=키스자산평가, 수협은행(舊)).
- **반대 방향의 공백도 있다.** 금투협에 올리긴 하지만 일부만 올리는 회사다. 삼성증권은 반년 동안 2건뿐이고 나머지는 삼성 채용 사이트에 올린다. "0건"만 보면 이런 회사를 놓친다. → 6절 커버리지 점검.

DB 기간이 5.5개월이라 "0건"은 "이 기간에 금투협에 안 올렸다"는 뜻이다. 채용을 안 한 것일 수도 있다.

### D. 금투협에 올리는 회사의 자체 채용 채널 (전수 확인, 2026-10-29)

**계기.** 메리츠증권은 반년 동안 금투협에 30건을 올렸지만 전부 팀 단위 경력·수시 채용이었다. 지금 진행 중인 대졸 공채(10/19~10/30)는 자체 사이트 `recruit-meritz.com`에만 있다.

**2026년 하반기 신입 공채·인턴이 금투협에 왔는지:**

| 금투협에 올라옴 | 금투협에 없음 (자체 채널에만) |
|---|---|
| 한국투자증권(일반 공채 5급), 신한투자증권(통합 직무·업무직·IPO 신입), 교보증권(5급), IBK투자증권(대졸/고졸), 부국증권, 하나자산운용·코리아에셋투자증권(인턴·신입) | 메리츠증권(대졸 공채), NH투자증권(대졸 공채·업무직 공채·PB 체험형 인턴), 키움증권(대졸 공채, `kiwoom.saramin.co.kr`), DB증권(DB그룹 공채·채용연계형 인턴), LS증권(채용전제형 인턴), 우리자산운용(하반기 공개 채용), 하나자산신탁(하반기 직원 채용) |

**범위.** 국내 증권 38곳, 자산운용 상위 34곳, 신탁 14곳, 선물 3곳, 유관기관·신평·채권평가·데이터·사무관리 31곳. 종금은 우리종금이 우리투자증권으로 전환되어 남은 회원사가 없다. 외국계 IB는 2절 A에서 따로 다뤘다.

**방법.**
1. Findar DB 공고 1,900건의 "사이트바로가기" 링크와 본문 URL에서 회사별 채용 사이트를 뽑았다. 회사가 실제로 쓰는 채용 시스템이 여기서 대부분 드러난다.
2. 각 사이트의 robots.txt를 Google 방식(가장 긴 규칙 우선)으로 판정했다. Python 기본 파서는 먼저 나온 규칙이 이기므로 `Disallow: / … Allow: /appsite/`를 잘못 읽는다.
3. 서버가 보내는 HTML에 공고 제목이 있는지 확인했다. 없으면 브라우저로 한 번 열어 목록을 어디서 불러오는지(XHR 주소) 봤다.
4. 링크가 없는 회사는 홈페이지의 채용 메뉴와 공채 보도·채용 포털 공고에서 접수처를 찾았다.

**판정 기준.**
- **자동**: 기존 어댑터나 robots.txt가 허용하는 경로로 목록을 얻는다.
- **자동(엔드포인트)**: 같은 사이트 안의 목록 API를 쓴다. robots.txt가 막지 않지만 사이트별 설정이 필요하다.
- **확인 필요**: 목록이 브라우저에서만 보이고, 데이터 경로를 아직 확인하지 않았다.
- **불가**: robots.txt가 데이터 경로를 금지하거나, 자동 요청을 차단한다(429). 우회하지 않는다.
- **금투협만**: 별도 채용 채널을 찾지 못했다. 금투협과 이메일 접수뿐이다.

- 회사 단위로는 120곳 모두 "어디를 봐야 하는지"가 정해졌다. 이것이 감시 목록의 초기값이다.

- 불가 채널은 두 가지로 보완한다.

## 3. 수집 구조

### 3.1 감시 목록 `data/company-watchlist.json`

회사 하나에 출처 여러 개를 둘 수 있다. 사용자가 `/settings` 또는 `/profile`에서 회사를 추가하거나 끈다. 초기값은 2절의 "확인" 항목으로 채운다.

```jsonc
{
  "companies": [
    {
      "name": "한국자산신탁",               // 표시용. 식별은 normalizeCompanyName(name)
      "segment": "A5 부동산신탁",          // 사용자 분류 그대로
      "sources": [{ "type": "greeting", "base": "https://careers.kait.com" }],
      "enabled": true
    },
    { "name": "한국거래소", "segment": "B 시장운영", "sources": [{ "type": "saraminAts", "base": "https://krx.saramin.co.kr" }] },
    { "name": "모건스탠리", "segment": "A1 외국계 IB", "sources": [{ "type": "workday", "tenant": "ms", "host": "ms.wd5.myworkdayjobs.com", "site": "External", "locationQuery": "Seoul" }] },
    { "name": "신영부동산신탁", "segment": "A5 부동산신탁", "sources": [{ "type": "pageWatch", "url": "http://www.shinyoungret.com?pages=job" }] },
    { "name": "한국신용평가", "segment": "B 신용평가", "sources": [{ "type": "saraminApi", "keyword": "한국신용평가" }] }
  ]
}
```

- 금투협 게시판은 그대로 전체 수집한다. 감시 목록은 금투협 **밖**만 다룬다.
- 금투협에 이미 꾸준히 올리는 회사는 감시 목록에 넣지 않는다. 일부만 올리는 회사(삼성증권 등)는 넣는다. 그러면 생기는 중복은 5절에서 합친다.

### 3.2 ATS 계열 어댑터

회사마다 파서를 따로 짜지 않는다. ATS 계열당 어댑터 하나로 여러 회사를 받는다.

| type | 대상(확인된 것) | 목록을 얻는 방법 | 본문 |

- `FindarResearch` UA를 쓰고, 호스트당 요청 간격을 1초 이상 둔다. 금투협의 1000ms 대기와 같은 원칙이다.
- 인증서 오류가 나면 http로 다시 시도하는 정도만 한다(`read_page`와 같은 방식). 인증서 검증을 끄지는 않는다.
- 차단 응답(401/403/429, 챌린지 페이지)이 오면 그 회사를 `blocked`로 표시하고 다음 수집을 건너뛴다. 우회하지 않는다.
- 외국계는 서울(또는 Korea) 근무지만 남긴다.

### 3.3 `pageWatch` — 자체 게시판 감시

ATS가 없는 회사의 자체 채용 게시판에 쓴다. 사이트마다 파서를 짜지 않는다.

1. 게시판 URL을 받아 온다. `lib/research-page-tool.ts`의 페이지 리더를 재사용한다(EUC-KR, 프레임, 사이트 공통 메뉴 제거, 같은 사이트 링크 목록).
2. 같은 사이트 링크 중 텍스트에 `채용|모집|공고|recruit|career`가 들어 있는 것을 후보로 뽑는다.
3. 지난번 후보 목록과 비교해서 새로 생긴 링크만 연다.
4. 연 페이지를 기존 요약기에 그대로 넣는다(회사명은 감시 목록 값을 쓴다). 마감일 같은 필드는 요약기가 이미 뽑는다.

비용은 새 글이 생겼을 때만 든다. 오탐(채용 안내·결과 발표 글)은 요약 결과 `positions`가 비면 저장하지 않는 것으로 거른다.

### 3.4 파이프라인 위치

- `GET /api/jobs`는 지금처럼 금투협을 수집하고, 그다음 감시 목록의 출처를 차례로 돈다. SSE 이벤트에 `source`(`kofia` | `watch:<type>`)와 회사명을 붙인다.
- 감시 목록 수집은 공고 수가 적다(회사당 0~수 건). 다만 요청 수는 회사 수에 비례하므로 **하루 1회**로 제한하고, 마지막 수집 시각은 `watch_runs` 테이블에 둔다. 사용자가 회사 하나를 수동으로 새로고침할 수 있게 한다.
- 출처 하나가 실패해도 나머지는 계속한다. 실패는 회사별 상태(`ok` | `failed` | `blocked` | `empty`)로 남긴다.

### 3.5 공채 시즌 감지 (불가 채널 보완)

불가 채널 24곳에 대형사 공채가 몰려 있다. 공고를 가져오지 못해도, 대형사 공채는 거의 항상 보도자료가 나온다(이번 하반기: 메리츠·NH·신한·LS·교보·DB·한투 모두 기사 확인).

- 대상: `manual`·`확인 필요` 회사 중 공채를 하는 곳(증권·운용 상위사, 유관기관).
- 시기: 공채가 몰리는 3~5월과 8~11월에만, 주 1회.
- 방법: 회사별로 "<회사명> 신입 공채" 웹 검색을 한 번 한다(회사 리서치와 같은 WebSearch, 저비용 모델). 결과에서 **올해·이번 시즌** 공채 보도가 있으면 회사명·기사 링크·접수 마감일만 뽑는다.
- 결과는 공고로 저장하지 않는다. 보드 상단에 "금투협에 없는 공채: NH투자증권 대졸 공채(~9/28) → 채용 사이트" 같은 알림으로만 띄운다. 사용자가 "공고로 추가"를 누르면 채용 사이트 URL을 `pageWatch` 한 건으로 넣는다.
- 비용: 회사 30곳 × 주 1회 × 시즌 약 20주 = 연 600회 검색. 감지된 회사만 사용자에게 보인다.

## 4. 식별자·스키마

1차 설계(2026-10-19)를 그대로 쓴다.

- KOFIA는 숫자 seq 그대로. 감시 목록 공고는 `<type>-<원본ID>`(`greeting-12345`, `saraminats-krx-3942`, `workday-ms-JR012345`, `page-<url 해시 12자리>`, `saramin-<id>`).
- `jobs`에 `source`, `sourceUrl`, `contentLevel`, `segment`(사용자 분류) 열을 추가한다.
- 숫자 seq를 전제로 한 4곳을 고친다: `selectCompanyJobsStmt`의 `CAST(seq AS INTEGER)`, `company-research.ts`·`sheet-sync.ts`의 KOFIA URL 고정, `JobBoard.tsx`의 "KOFIA 원문 보기", 그리고 Apps Script의 `^\d+$` 검사(재배포 필요).

## 5. 중복 제거

감시 목록이 금투협 밖만 다루므로 중복은 1차 설계보다 적다. 남는 경우는 두 가지다.

1. **같은 회사가 금투협과 자사 ATS에 둘 다 올림.** 삼성증권처럼 일부만 올리는 회사를 감시 목록에 넣었을 때 생긴다.
2. **같은 회사의 두 출처 사이.** 예를 들어 코스콤의 사람인 기업용 사이트와 자체 게시판.

판정은 1차 설계 6절을 그대로 쓴다(AI 없음, 요약 전에 판정).
- 회사 키: `(구.…)` 제거 → `normalizeCompanyName` → `hangulizeLatin` → 별칭표
- 제목 키: `[회사명]`·마감 표기·상투어 제거
- 판정 기준: 공고 번호가 든 공고 주소가 같으면 바로 중복, 같은 채용 사이트의 다른 공고 주소면 다른 공고. 그 밖에는 마감일 ±1일 + 제목 2-gram Dice ≥ 0.7, 마감일이 없으면 ≥ 0.85(10절)
- 대표 공고: 사용자 상태가 있는 쪽 > 금투협 > ATS > pageWatch > 사람인 API
- `job_links` 테이블에 연결을 기록하고, 사용자가 "중복 아님"으로 분리할 수 있게 한다

감시 목록 회사는 이름을 직접 정하므로 회사 키 매칭이 쉽다. 외국계 영문명("Morgan Stanley")과 금투협 회원명("모간스탠리인터내셔날증권 서울지점")은 감시 목록 항목에 `aliases`를 두어 연결한다.

## 6. 커버리지 점검 (부분 게시 회사 찾기)

"0건"만 보면 삼성증권 같은 부분 게시 회사를 놓친다. 그래서 점검 화면을 따로 둔다.

- `/settings` → **수집 범위** 표: 회원사 명부(업권), 사용자 분류, 최근 6개월 금투협 게시 수, 감시 목록 등록 여부·출처·마지막 결과.
- 회원사 명부는 금투협 회원사현황 페이지에서 월 1회 받는다(이번 조사에 쓴 방식과 같음: 업권별 페이지 + 자문사 30건 단위 페이지).
- 감시 목록 출처가 돌아가기 시작하면 "금투협 게시 수 대비 자사 ATS 공고 수"를 같은 표에 보여 준다. 이 비율이 낮은 회사가 부분 게시 회사다.
- 사용자 분류(A1~C)에는 회원 업권에 없는 회사(거래소·코스콤·PE·VC·회계법인)도 들어가므로, 분류는 감시 목록의 `segment`가 기준이다.

## 7. 1차 설계에서 바뀐 것

| 항목 | 1차(10-19) | 지금 |
|---|---|---|
| 기본 단위 | 출처 사이트(잡알리오·사람인) | 회사 감시 목록 + ATS 계열 어댑터 |
| 잡알리오 | 금융 공공기관 수집 | **보류.** 사용자 분류 안의 공공 성격 기관(예탁결제원·거래소·증권금융)은 모두 사람인 기업용 사이트로 받을 수 있다. 은행권 공기업(산은·기은·수은·KIC)은 분류 밖 |
| 사람인 오픈API | 금융 업종 전체 수집 | 경로를 못 찾은 회사에 한해 회사명으로 검색하는 보조 수단. 승인 대기 중에도 다른 단계는 진행 가능 |
| 중복 제거 | 사이트 간 대량 중복 | 부분 게시 회사·다중 출처 회사에 한정 |

## 8. 단계

1. **출처 추상화와 스키마**(동작 변화 없음): `source`·`sourceUrl` 열, `job_links`, 숫자 seq 전제 4곳 수정.
2. **감시 목록 + `greeting`·`saraminAts` 어댑터**: 부동산신탁, 거래소·예탁결제원·증권금융·코스콤, 아이알큐더스, 키움증권 공채. 키가 필요 없고 robots.txt도 허용한다. 감시 목록 초기값은 2절 D 표 전체(`manual` 포함)로 채운다.
3. **중복 판정**: `lib/job-dedup.ts` + `scripts/tests/job-dedup.cjs`. 2절 D 대상은 대부분 금투협에도 경력 공고를 올리므로, 3단계 이후 어댑터보다 먼저 끝낸다.
4. **`pageWatch`·`recruiterAppsite`·`endpoint`**: 신한투자증권, 우리·하나자산운용, 하나자산신탁, SK·LS증권, IBK·미래에셋·한투. 공채가 실제로 빠진 곳이 여기 들어 있다.
5. **공채 시즌 감지(3.5절)와 `manual` 바로가기 목록**.
6. **`workday` 어댑터**: 모건스탠리·도이치부터. 나머지 외국계는 테넌트를 하나씩 찾아 추가하고, robots.txt가 금지하면 넣지 않는다.
7. **커버리지 점검 화면**.
8. **`saraminApi`**: 승인이 나면.
9. **"확인 필요" 13곳 재조사**: CareerLink(메리츠·KB자산운용), samsungcareers, applyin, 토스(Greenhouse 보드 토큰). 데이터 경로를 robots.txt와 함께 확인한 뒤 어댑터를 정한다.

## 9. 결정이 필요한 것

1. **인접 산업(C)을 어디까지 넣을지.** PEF는 공개 공고가 거의 없어서 수집할 것이 적다. VC·회계법인 FAS·가상자산은 회사별로 넣을 수 있다.
2. **외국계 운용사·외국계 은행 서울지점**을 감시 목록에 넣을지(사용자 분류에는 외국계 IB만 있음).
3. **골드만삭스**: robots.txt가 목록을 금지하므로 자동 수집은 하지 않는 것을 권한다. 사용자가 공고 URL을 직접 붙여 넣으면 그 한 건만 가져오는 "URL로 추가" 기능으로 대신할 수 있다(robots.txt가 `/roles/`는 허용).
4. **공채 시즌 감지(3.5절)를 둘지.** 불가 채널을 보완하는 유일한 자동 수단이지만 웹 검색 비용이 든다(연 약 600회). 끄면 `manual` 바로가기 목록만 남는다.
5. **은행·보험을 넣을지.** 금투협 회원(은행 27, 보험 8)이지만 처음 받은 분류체계에 없어서 이번 전수 확인에서 뺐다. 은행은 신탁·IB·자금시장 부서 공고가 금투협에 70건 올라와 있다.

## 10. 구현 결과와 설계에서 바뀐 것 (2026-10-29)

**구현한 것(1~3단계).** `lib/job-source.ts`(출처·원문 링크), `lib/company-watchlist.ts`(감시 목록 초기값 = 2절 D 표, 금투협만 회사 제외), `lib/watch-fetch.ts`(robots.txt 가장 긴 규칙 우선·호스트당 1초·차단 시 우회 없음), `lib/watch-adapters.ts`(그리팅·사람인 기업 채용 사이트), `lib/job-dedup.ts`·`job_links`(중복), `lib/company-watch.ts`(하루 한 번, `watch_runs`), 설정 → 수집 범위. 테스트 `scripts/tests/company-watch.cjs`.

**설계와 달라진 점.**
- `source`·`sourceUrl` 열을 두지 않았다. 출처는 seq 형태로 정해지고(숫자 = 금투협, `manual-`, `greeting-<id>`, `saraminats-<slug>-<id>`), 금투협 밖 공고의 원문 주소는 `siteUrl`이다. seq가 바뀌지 않으니 두 값이 어긋날 일이 없다.
- 중복 판정(3단계)을 2단계와 같이 넣었다. 첫 실제 수집에서 KIS자산평가·NICE신용평가·KB증권·BNK투자증권·넥스트증권·대신자산신탁 공고 12건이 금투협과 겹쳤다.
- 제목 기준을 0.6에서 0.7로 올렸다. BNK "CM부 백오피스"와 "주식운용 백오피스"(마감 하루 차이)가 0.6으로 묶였다. 같은 채용 사이트의 서로 다른 공고 주소면 다른 공고로 본다. 주소는 공고 번호(세 자리 이상 숫자)가 있을 때만 근거로 쓴다 — KIS 금투협 공고의 사이트바로가기가 `…/ko/home`이었다. 그리팅 주소의 언어 경로(`/ko`)는 무시한다(금투협에는 `/o/241147`로 적힌다).
- 마감일 없는 채용 사이트 공고(그리팅 상시 채용)는 목록에서 내려가면 `jobs.sourceClosedAt`으로 닫는다. 인재풀 등록 공고와 마감일 없이 반년 넘게 열린 공고는 받지 않는다.
- 대한토지신탁 채용 사이트는 robots.txt가 전체 금지라 "자동 수집 불가"로 옮겼다(2절 D 표의 사람인 행 정정).
- 사람인 기업 채용 사이트는 화면이 두 가지다: `/service/{slug}/{id}/applicant/apply/index.asp`(채용 한 건, 본문 `recruit_default.asp`)와 `/apply_site/recruit/list`. "진행중" 표시는 마감 뒤에도 남아 믿지 않는다(예탁결제원 9/1 마감 공고가 10/29에도 "진행중").

**첫 실제 수집(2026-10-29, DB 사본).** 17곳 55초. 새 공고 27건(아이알큐더스 8, 넥스트증권 15 — 하루 15건 상한, 거래소 2, 예탁결제원 1, 증권금융 1, 한국자산신탁 인턴 1, KIS 0), 금투협 중복 12건 연결. 키움 대졸 공채는 9/13 마감이라 제외됐다.
